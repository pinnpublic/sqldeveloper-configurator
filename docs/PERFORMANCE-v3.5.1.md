# 3.5.1 방향키·반응성 검토

## 확인한 원인과 수정

1. **아래 방향키 정지:** Oracle 기본 동작은 글꼴 높이만큼 Y 좌표를 이동했다. 노트의 추가 줄 간격 때문에 이동 후에도 같은 표시 행이었다. 기본 `BasicAction.getFontHeight`의 표시 행 높이를 맞춰 방향키·Shift 선택·페이지 이동을 연결했다.
2. **자동 줄바꿈 경계의 이동:** 한 표시 행의 끝 오프셋과 다음 행의 시작 오프셋이 같다. native caret의 Forward bias에서 짧은 행 끝을 반환하면 다음 행을 건너뛰거나 Up이 같은 위치에 머물렀다. 해당 행에 속한 마지막 유효 문자 위치로 제한한다.
3. **캐시가 사실상 동작하지 않음:** native `updateMetrics`는 변경이 없는 좌표 조회·그리기에서도 호출된다. 3.5.0은 메서드 진입 때마다 캐시를 지웠고 다음 조회가 문서 전체의 줄바꿈을 다시 계산했다. 캐시는 문서 revision·너비·글꼴·native 높이로 판정하며, 접기 변경에서만 명시적으로 버린다.
4. **편집·화면 갱신의 과도한 작업:** 추가 줄 간격만 사용하는 경우에는 native 좌표를 직접 변환한다. 줄바꿈 사용 시 변경되지 않은 줄의 폭 계산을 재사용한다. 매 span 조회의 전체 행 순회, 그리기 중 불필요한 문서 전체 복사, 화면 밖 구분선 순회를 제거했다.
5. **공유 UI 스레드의 추가 부하:** 선택·현재 줄 강조 등 모든 property change에 전체 배치·스크롤 영역 repaint를 요청하던 코드를 제한했다. 주기적인 설정 파일 읽기는 daemon 작업 스레드에서 수행하고, 변경된 옵션 반영만 EDT에서 실행한다.

SQL Developer의 편집기와 질의 결과 화면은 같은 Swing EDT를 사용한다. 편집기 작업이 EDT를 오래 점유하면 다른 UI 동작도 기다리게 된다. DB 실행 시간은 실제 쿼리를 실행하지 않아 측정하지 않았다.

## 같은 입력으로 비교한 결과

실제 Oracle 26.2 편집기, Java 17, 24pt, 너비 760px, 추가 줄 간격 30%, 화선지 질감, 메모리 SQL 1,000줄, 자동 줄바꿈 켜짐. 각각 별도 JVM에서 3.5.0 보관 JAR와 수정본을 실행했다. 측정은 이 PC의 샘플이며 일반적인 지연 보장은 아니다.

| 작업 | 3.5.0 | 3.5.1 |
| --- | ---: | ---: |
| model/view 좌표 왕복 20회 | 234.449ms | 0.150ms |
| 화면 그리기 3회 | 64.504ms | 3.109ms |
| 삽입·표시·삭제 3회 | 79.719ms | 10.794ms |

추가 검사: 서로 다른 문장 10,000줄에서 좌표 왕복·span 조회 100회 0.93ms, 삽입·표시·삭제 3회 37.20ms. 구분선 10,000줄에서 화면 그리기 5회 4.03ms.

## 동작 검증

- Oracle 실제 caret-down/up 및 selection-down/up: 줄바꿈 켜짐/꺼짐 × 7/24/50pt × 추가 줄 간격 0/30/90/200%, 총 24개 조합.
- Page Up/Down, 빈 줄·탭·한글·긴 줄과 편집 후 원문·복사 문자열 유지.
- 기존 결과표 24/34/50pt, native renderer·행/셀 선택, 글꼴 동기화, 자동 줄바꿈, 9종 `---` 구분선.
- 12종 노트 무늬·10종 선·36개 질감 선택, 강조 투명도·선택 배경, native gutter·스크롤, 환경설정 적용·취소.
- 설치·업그레이드·재적용·원본 복구, 기존 설정 보존.
